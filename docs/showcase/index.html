4 · Form controls and validation

The invalid style is driven by aria-invalid, so what a sighted user sees and what a screen reader announces can never disagree. Error and success carry equal weight — master plan §6 requires that a failed inquiry can never borrow the success styling.

5 · Tabs

WAI-ARIA tabs pattern: one tab in the tab order, arrow keys move and activate, Home and End jump to the ends. Try it with the keyboard. The scaffolding for a future service explorer — not the explorer itself.

Panel content is supplied by the page. The primitive supplies structure, keyboard behaviour and the accessible names only.

6 · Disclosure / accordion

A button carrying aria-expanded controls the region it names. Closed panels use hidden, so their content is out of the tab order and out of the accessibility tree. This is how a technical page stays short without losing depth.

Detail stays here until it is asked for, which keeps the page scannable for a reader who only wants to know whether to call.

7 · Overlays, layering and motion

Primitives only — no inquiry drawer and no dialog are built here. This establishes the layering and travel so the first one built behaves predictably. Escape closes, and focus returns to the control that opened it.

Layering scale

TokenValueUse
--rce-z-raised10Lifted cards, sticky section heads
--rce-z-sticky100Site header
--rce-z-overlay200Scrim behind drawer or dialog
--rce-z-drawer210Inquiry drawer, mobile menu
--rce-z-dialog220Dialogs
--rce-z-toast300Transient messages

Motion

TokenValueUse
--rce-duration-fast120msHover, focus, button press

All of it is disabled under prefers-reduced-motion: reduce.
